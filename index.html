💻 Programación Orientada a Objetos

Conceptos Básicos Explicados de Forma Simple

1¿Qué es una CLASE?

📋 Definición:

Una clase es como un molde o plantilla que define las características (atributos) y comportamientos (métodos) que tendrán los objetos creados a partir de ella.

🍪

Piensa en un molde de galletas

El molde define la forma, pero no es la galleta en sí

class Persona { // Atributos (características) nombre: string; edad: number; constructor(nombre: string, edad: number) { this.nombre = nombre; this.edad = edad; } saludar(): string { return "Hola, soy " + this.nombre; } }
  • Define la estructura de los objetos
  • Contiene atributos (datos) y métodos (funciones)
  • Es reutilizable para crear múltiples objetos

2¿Qué es un OBJETO?

📦 Definición:

Un objeto es una instancia concreta de una clase. Es algo real y específico creado usando el molde (clase).

👤

De la clase Persona creamos objetos reales

Juan (25 años) y María (30 años) son objetos diferentes de la misma clase

const persona1 = new Persona("Juan", 25); const persona2 = new Persona("María", 30); persona1.saludar(); // "Hola, soy Juan" persona2.saludar(); // "Hola, soy María"

CLASE

Es abstracta (el molde). Define la estructura.

OBJETO

Es concreto (la galleta). Tiene valores específicos.

3¿Qué es la HERENCIA?

🧬 Definición:

La herencia permite que una clase herede atributos y métodos de otra clase. La clase hija obtiene todo de la clase padre y puede agregar sus propias características.

👨‍👦

Como la herencia familiar

Un hijo hereda características de sus padres, pero también tiene las suyas propias

class Estudiante extends Persona { carrera: string; constructor(nombre: string, edad: number, carrera: string) { super(nombre, edad); this.carrera = carrera; } estudiar(): string { return "Estudiando " + this.carrera; } } const estudiante = new Estudiante("Carlos", 20, "Ingeniería"); estudiante.saludar(); // Heredado de Persona estudiante.estudiar(); // Propio de Estudiante
  • Permite reutilizar código
  • Crea relaciones "es un" (Estudiante ES UNA Persona)
  • La clase hija puede extender funcionalidad

4¿Qué es una CLASE ABSTRACTA?

🚫 Definición:

Una clase abstracta es una clase que NO se puede instanciar directamente. Solo sirve como base para otras clases y define métodos que las clases hijas DEBEN implementar.

🐾

Concepto de "Animal"

No existe un "animal" genérico. Existen perros, gatos, etc.

abstract class Animal { nombre: string; constructor(nombre: string) { this.nombre = nombre; } abstract hacerSonido(): string; } class Perro extends Animal { hacerSonido() { return "¡Guau guau!"; } } class Gato extends Animal { hacerSonido() { return "¡Miau miau!"; } }
  • No se puede instanciar directamente
  • Define estructura común para clases hijas
  • Obliga a implementar ciertos métodos

5¿Qué es el POLIMORFISMO?

🎭 Definición:

Polimorfismo significa "muchas formas". Es la capacidad de diferentes clases de responder al mismo método de manera diferente.

🔊

Mismo método, diferentes resultados

Todos los animales "hacen sonido", pero cada uno lo hace diferente

const animales: Animal[] = [ new Perro("Firulais"), new Gato("Michi") ]; animales.forEach(animal => { console.log(animal.hacerSonido()); }); // ¡Guau guau! // ¡Miau miau!
  • Mismo método, diferentes implementaciones
  • Permite código más flexible y extensible
  • Facilita agregar nuevos tipos sin cambiar código existente

6¿Qué es una INTERFACE?

📜 Definición:

Una interface es un contrato que define QUÉ métodos debe tener una clase, pero no CÓMO implementarlos.

✈️

Contrato de "poder volar"

Tanto un pájaro como un avión pueden volar, aunque son muy diferentes

interface Volador { volar(): string; aterrizar(): string; } class Pajaro implements Volador { volar() { return "Batiendo las alas"; } aterrizar() { return "Posándose en una rama"; } } class Avion implements Volador { volar() { return "Impulsado por motores"; } aterrizar() { return "Aterrizando en pista"; } }
  • Define un contrato que las clases deben cumplir
  • Permite que clases diferentes compartan comportamientos
  • Una clase puede implementar múltiples interfaces

7¿Qué es el ENCAPSULAMIENTO?

🔒 Definición:

El encapsulamiento es proteger los datos internos de una clase y controlar cómo se accede a ellos mediante métodos públicos.

🏦

Como una cuenta bancaria

No puedes cambiar el saldo directamente, solo a través de operaciones controladas

class CuentaBancaria { private saldo: number; constructor(saldoInicial: number) { this.saldo = saldoInicial; } getSaldo(): number { return this.saldo; } depositar(cantidad: number): void { if (cantidad > 0) this.saldo += cantidad; } retirar(cantidad: number): boolean { if (cantidad > 0 && cantidad <= this.saldo) { this.saldo -= cantidad; return true; } return false; } }

🔓 public

Accesible desde cualquier lugar

🔒 private

Solo accesible dentro de la clase

🔐 protected

Accesible en la clase y sus hijas

Deber 1: Consumo de una API

Consumo de la API de usuarios — jsonplaceholder.typicode.com

📖¿Qué es una API?

📋 Definición:

Una API (Application Programming Interface) es una interfaz que permite que dos aplicaciones se comuniquen entre sí. En desarrollo móvil y web, usamos APIs para obtener datos de un servidor externo mediante peticiones HTTP.

🔄

Flujo de consumo de una API

App → Petición HTTP (GET) → Servidor API → Respuesta JSON → App muestra los datos

// Consumo de API con fetch() en JavaScript const url = "https://jsonplaceholder.typicode.com/users"; fetch(url) .then(response => response.json()) .then(data => { console.log(data); // Array de usuarios }) .catch(error => { console.log("Error:", error); });
  • Se usa el método GET para obtener datos
  • La respuesta llega en formato JSON
  • Se maneja con .then() o async/await

🔗API Utilizada

🌐 Endpoint:

https://jsonplaceholder.typicode.com/users

🔐 Deber 2: Autenticación

Email/Password y Google Sign-In con Firebase Authentication — Kotlin (Android)

📖¿Qué es Firebase Authentication?

📋 Definición:

Firebase Authentication es un servicio de Google que permite autenticar usuarios de forma segura usando distintos proveedores: correo/contraseña, Google, Facebook, etc. Maneja todo el backend de seguridad automáticamente.

🔄

Flujo de Autenticación

Usuario ingresa credenciales → Firebase verifica → Retorna token de sesión → App permite acceso

  • No necesitas manejar contraseñas manualmente
  • Firebase cifra y protege los datos de los usuarios
  • Soporta múltiples proveedores de identidad
  • Provee un objeto FirebaseUser con los datos del usuario activo

⚙️Configuración en build.gradle

📦 Dependencias necesarias:

Agrega estas dependencias en tu archivo build.gradle (app) para habilitar Firebase Auth y Google Sign-In.

// build.gradle (app) dependencies { // Firebase Authentication implementation("com.google.firebase:firebase-auth-ktx") // Google Sign-In implementation("com.google.android.gms:play-services-auth:20.7.0") }

📧Autenticación con Email/Password

📋 Registro e inicio de sesión:

Firebase permite crear cuentas y autenticar usuarios con correo electrónico y contraseña con solo unas pocas líneas de Kotlin.

class AuthActivity : AppCompatActivity() { private val auth = FirebaseAuth.getInstance() // REGISTRO de nuevo usuario fun registrarUsuario(email: String, password: String) { auth.createUserWithEmailAndPassword(email, password) .addOnCompleteListener { task -> if (task.isSuccessful) { Toast.makeText(this, "Registro exitoso", Toast.LENGTH_SHORT).show() } else { Toast.makeText(this, "Error: ${task.exception?.message}", Toast.LENGTH_SHORT).show() } } } // INICIO DE SESIÓN con email y password fun iniciarSesion(email: String, password: String) { auth.signInWithEmailAndPassword(email, password) .addOnCompleteListener { task -> if (task.isSuccessful) { val user = auth.currentUser Toast.makeText(this, "Bienvenido ${user?.email}", Toast.LENGTH_SHORT).show() } else { Toast.makeText(this, "Credenciales incorrectas", Toast.LENGTH_SHORT).show() } } } // CERRAR SESIÓN fun cerrarSesion() { auth.signOut() } }

🔵Autenticación con Google

📋 Google Sign-In:

Permite al usuario iniciar sesión con su cuenta de Google. Se usa GoogleSignInClient para abrir el selector de cuenta y luego Firebase valida el token.

class GoogleAuthActivity : AppCompatActivity() { private val auth = FirebaseAuth.getInstance() private lateinit var googleSignInClient: GoogleSignInClient private val RC_SIGN_IN = 9001 override fun onCreate(savedInstanceState: Bundle?) { super.onCreate(savedInstanceState) // Configurar Google Sign-In val gso = GoogleSignInOptions.Builder(GoogleSignInOptions.DEFAULT_SIGN_IN) .requestIdToken(getString(R.string.default_web_client_id)) .requestEmail() .build() googleSignInClient = GoogleSignIn.getClient(this, gso) } // Iniciar flujo de Google Sign-In fun signInConGoogle() { val signInIntent = googleSignInClient.signInIntent startActivityForResult(signInIntent, RC_SIGN_IN) } // Recibir resultado del selector de cuenta Google override fun onActivityResult(requestCode: Int, resultCode: Int, data: Intent?) { super.onActivityResult(requestCode, resultCode, data) if (requestCode == RC_SIGN_IN) { val task = GoogleSignIn.getSignedInAccountFromIntent(data) val account = task.getResult(ApiException::class.java) firebaseAuthConGoogle(account.idToken!!) } } // Autenticar en Firebase con el token de Google private fun firebaseAuthConGoogle(idToken: String) { val credential = GoogleAuthProvider.getCredential(idToken, null) auth.signInWithCredential(credential) .addOnCompleteListener { task -> if (task.isSuccessful) { val user = auth.currentUser Toast.makeText(this, "Bienvenido ${user?.displayName}", Toast.LENGTH_SHORT).show() } } } }
  • El idToken de Google se intercambia por una sesión de Firebase
  • Firebase guarda al usuario automáticamente en Authentication Console
  • Puedes obtener nombre, email y foto del usuario de Google

👤Obtener usuario actual

val user = FirebaseAuth.getInstance().currentUser if (user != null) { val nombre = user.displayName // Nombre del usuario val email = user.email // Correo electrónico val foto = user.photoUrl // URL de foto de perfil val uid = user.uid // ID único del usuario } else { // No hay sesión activa → redirigir a Login }

🔥 Deber 3: CRUD con Realtime Database

Crear, Leer, Actualizar y Eliminar datos con Firebase Realtime Database — Kotlin (Android)

📖¿Qué es Firebase Realtime Database?

📋 Definición:

Firebase Realtime Database es una base de datos NoSQL alojada en la nube que sincroniza datos en tiempo real entre todos los clientes conectados. Los datos se almacenan en formato JSON y cualquier cambio se refleja instantáneamente en la app.

☁️

Sincronización en tiempo real

App escribe dato → Firebase actualiza → Todos los dispositivos conectados reciben el cambio al instante

  • Base de datos NoSQL en la nube
  • Sincronización en tiempo real sin necesidad de polling
  • Funciona también en modo offline
  • Los datos se estructuran como un árbol JSON

⚙️Configuración

// build.gradle (app) implementation("com.google.firebase:firebase-database-ktx") // Obtener referencia a la base de datos val database = FirebaseDatabase.getInstance() val ref = database.getReference("productos") // Nodo raíz

➕CREATE — Crear datos

📋 Insertar un nuevo registro:

Se usa push() para generar una clave única automáticamente, o setValue() con una clave propia.

data class Producto( val nombre: String = "", val precio: Double = 0.0, val stock: Int = 0 ) fun crearProducto(nombre: String, precio: Double, stock: Int) { val ref = FirebaseDatabase.getInstance().getReference("productos") val nuevoId = ref.push().key!! // Genera ID único val producto = Producto(nombre, precio, stock) ref.child(nuevoId).setValue(producto) .addOnSuccessListener { Toast.makeText(this, "Producto creado ✓", Toast.LENGTH_SHORT).show() } .addOnFailureListener { Toast.makeText(this, "Error al crear", Toast.LENGTH_SHORT).show() } }

📋READ — Leer datos

📋 Escuchar cambios en tiempo real:

Con addValueEventListener la app recibe los datos automáticamente cada vez que cambian en Firebase.

fun leerProductos() { val ref = FirebaseDatabase.getInstance().getReference("productos") ref.addValueEventListener(object : ValueEventListener { override fun onDataChange(snapshot: DataSnapshot) { val lista = mutableListOf<Producto>() for (item in snapshot.children) { val producto = item.getValue(Producto::class.java) producto?.let { lista.add(it) } } // Actualizar RecyclerView con la lista adapter.actualizarLista(lista) } override fun onCancelled(error: DatabaseError) { Toast.makeText(this@MainActivity, error.message, Toast.LENGTH_SHORT).show() } }) }

✏️UPDATE — Actualizar datos

📋 Modificar campos específicos:

Se usa updateChildren() para actualizar solo los campos que cambiaron, sin sobreescribir todo el registro.

fun actualizarProducto(id: String, nuevoPrecio: Double, nuevoStock: Int) { val ref = FirebaseDatabase.getInstance().getReference("productos") val cambios = mapOf( "precio" to nuevoPrecio, "stock" to nuevoStock ) ref.child(id).updateChildren(cambios) .addOnSuccessListener { Toast.makeText(this, "Actualizado ✓", Toast.LENGTH_SHORT).show() } }

🗑️DELETE — Eliminar datos

📋 Eliminar un registro:

Se usa removeValue() sobre el nodo específico que quieres eliminar.

fun eliminarProducto(id: String) { val ref = FirebaseDatabase.getInstance().getReference("productos") ref.child(id).removeValue() .addOnSuccessListener { Toast.makeText(this, "Eliminado ✓", Toast.LENGTH_SHORT).show() } .addOnFailureListener { Toast.makeText(this, "Error al eliminar", Toast.LENGTH_SHORT).show() } }

➕ CREATE

push().key + setValue()

📋 READ

addValueEventListener()

✏️ UPDATE

updateChildren()

🗑️ DELETE

removeValue()

🗄️ Deber 4: CRUD con Room

Persistencia de datos local con Room Database — Kotlin (Android)

📖¿Qué es Room?

📋 Definición:

Room es una biblioteca de Android Jetpack que proporciona una capa de abstracción sobre SQLite. Permite trabajar con bases de datos locales de forma más sencilla y segura usando anotaciones de Kotlin.

📱

Persistencia local sin internet

Los datos se guardan directamente en el dispositivo. Funciona sin conexión y es ideal para datos del usuario.

  • Abstracción sobre SQLite nativo de Android
  • Usa anotaciones para definir tablas y consultas
  • Compatible con LiveData y Flow para actualizaciones reactivas
  • Verifica las consultas SQL en tiempo de compilación

⚙️Configuración

// build.gradle (app) plugins { id("com.google.devtools.ksp") } dependencies { val roomVersion = "2.6.1" implementation("androidx.room:room-runtime:$roomVersion") implementation("androidx.room:room-ktx:$roomVersion") ksp("androidx.room:room-compiler:$roomVersion") }

1️⃣Entity — La tabla

📋 @Entity define la tabla en la base de datos:

Cada clase anotada con @Entity se convierte en una tabla de SQLite. Cada propiedad es una columna.

@Entity(tableName = "productos") data class Producto( @PrimaryKey(autoGenerate = true) val id: Int = 0, @ColumnInfo(name = "nombre") val nombre: String, @ColumnInfo(name = "precio") val precio: Double, @ColumnInfo(name = "stock") val stock: Int )

2️⃣DAO — Las operaciones CRUD

📋 @Dao contiene todas las consultas:

El Data Access Object define las funciones para interactuar con la base de datos usando anotaciones SQL.

@Dao interface ProductoDao { // CREATE - Insertar producto @Insert(onConflict = OnConflictStrategy.REPLACE) suspend fun insertar(producto: Producto) // READ - Obtener todos los productos @Query("SELECT * FROM productos ORDER BY nombre ASC") fun obtenerTodos(): Flow<List<Producto>> // READ - Buscar por ID @Query("SELECT * FROM productos WHERE id = :id") suspend fun obtenerPorId(id: Int): Producto? // UPDATE - Actualizar producto @Update suspend fun actualizar(producto: Producto) // DELETE - Eliminar producto @Delete suspend fun eliminar(producto: Producto) // DELETE - Eliminar todos @Query("DELETE FROM productos") suspend fun eliminarTodos() }

3️⃣Database — La base de datos

📋 @Database conecta todo:

La clase abstracta anotada con @Database es el punto de entrada principal. Se crea como Singleton para evitar múltiples instancias.

@Database(entities = [Producto::class], version = 1, exportSchema = false) abstract class AppDatabase : RoomDatabase() { abstract fun productoDao(): ProductoDao companion object { @Volatile private var INSTANCE: AppDatabase? = null fun getInstance(context: Context): AppDatabase { return INSTANCE ?: synchronized(this) { Room.databaseBuilder( context.applicationContext, AppDatabase::class.java, "mi_base_de_datos" ).build().also { INSTANCE = it } } } } }

4️⃣Uso en la Activity

class MainActivity : AppCompatActivity() { private lateinit var dao: ProductoDao override fun onCreate(savedInstanceState: Bundle?) { super.onCreate(savedInstanceState) dao = AppDatabase.getInstance(this).productoDao() // Observar cambios en tiempo real con Flow lifecycleScope.launch { dao.obtenerTodos().collect { lista -> adapter.actualizarLista(lista) } } } // Insertar nuevo producto private fun agregarProducto() { lifecycleScope.launch { dao.insertar(Producto(nombre = "Laptop", precio = 999.99, stock = 5)) } } // Eliminar producto private fun borrar(producto: Producto) { lifecycleScope.launch { dao.eliminar(producto) } } }

@Entity

Define la tabla y sus columnas

@Dao

Define las operaciones CRUD

@Database

Punto de entrada, crea la BD

Flow

Actualiza la UI en tiempo real
