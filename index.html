💻 Programación Orientada a Objetos

Conceptos Básicos Explicados de Forma Simple

1¿Qué es una CLASE?

📋 Definición:

Una clase es como un molde o plantilla que define las características (atributos) y comportamientos (métodos) que tendrán los objetos creados a partir de ella.

🍪

Piensa en un molde de galletas

El molde define la forma, pero no es la galleta en sí

class Persona { nombre: string; edad: number; constructor(nombre: string, edad: number) { this.nombre = nombre; this.edad = edad; } saludar(): string { return "Hola, soy " + this.nombre; } }
  • Define la estructura de los objetos
  • Contiene atributos (datos) y métodos (funciones)
  • Es reutilizable para crear múltiples objetos

2¿Qué es un OBJETO?

📦 Definición:

Un objeto es una instancia concreta de una clase. Es algo real y específico creado usando el molde (clase).

👤

De la clase Persona creamos objetos reales

Juan (25 años) y María (30 años) son objetos diferentes de la misma clase

const persona1 = new Persona("Juan", 25); const persona2 = new Persona("María", 30); persona1.saludar(); // "Hola, soy Juan" persona2.saludar(); // "Hola, soy María"

CLASE

Es abstracta (el molde). Define la estructura.

OBJETO

Es concreto (la galleta). Tiene valores específicos.

3¿Qué es la HERENCIA?

🧬 Definición:

La herencia permite que una clase herede atributos y métodos de otra clase. La clase hija obtiene todo de la clase padre y puede agregar sus propias características.

👨‍👦

Como la herencia familiar

Un hijo hereda características de sus padres, pero también tiene las suyas propias

class Estudiante extends Persona { carrera: string; constructor(nombre: string, edad: number, carrera: string) { super(nombre, edad); this.carrera = carrera; } estudiar(): string { return "Estudiando " + this.carrera; } }
  • Permite reutilizar código
  • Crea relaciones "es un" (Estudiante ES UNA Persona)
  • La clase hija puede extender funcionalidad

4¿Qué es una CLASE ABSTRACTA?

🚫 Definición:

Una clase abstracta NO se puede instanciar directamente. Solo sirve como base para otras clases.

🐾

Concepto de "Animal"

No existe un "animal" genérico. Existen perros, gatos, etc.

abstract class Animal { nombre: string; constructor(nombre: string) { this.nombre = nombre; } abstract hacerSonido(): string; } class Perro extends Animal { hacerSonido() { return "¡Guau!"; } } class Gato extends Animal { hacerSonido() { return "¡Miau!"; } }
  • No se puede instanciar directamente
  • Define estructura común para clases hijas
  • Obliga a implementar ciertos métodos

5¿Qué es el POLIMORFISMO?

🎭 Definición:

Polimorfismo significa "muchas formas". Es la capacidad de diferentes clases de responder al mismo método de manera diferente.

🔊

Mismo método, diferentes resultados

Todos los animales "hacen sonido", pero cada uno lo hace diferente

const animales: Animal[] = [new Perro("Firulais"), new Gato("Michi")]; animales.forEach(a => console.log(a.hacerSonido())); // ¡Guau! / ¡Miau!
  • Mismo método, diferentes implementaciones
  • Permite código más flexible y extensible
  • Facilita agregar nuevos tipos sin cambiar código existente

6¿Qué es una INTERFACE?

📜 Definición:

Una interface es un contrato que define QUÉ métodos debe tener una clase, pero no CÓMO implementarlos.

✈️

Contrato de "poder volar"

Tanto un pájaro como un avión pueden volar, aunque son muy diferentes

interface Volador { volar(): string; aterrizar(): string; } class Pajaro implements Volador { volar() { return "Batiendo las alas"; } aterrizar() { return "Posándose en una rama"; } }
  • Define un contrato que las clases deben cumplir
  • Permite que clases diferentes compartan comportamientos
  • Una clase puede implementar múltiples interfaces

7¿Qué es el ENCAPSULAMIENTO?

🔒 Definición:

El encapsulamiento es proteger los datos internos de una clase y controlar cómo se accede a ellos mediante métodos públicos.

🏦

Como una cuenta bancaria

No puedes cambiar el saldo directamente, solo a través de operaciones controladas

class CuentaBancaria { private saldo: number; constructor(s: number) { this.saldo = s; } getSaldo() { return this.saldo; } depositar(n: number) { if (n > 0) this.saldo += n; } retirar(n: number) { if (n > 0 && n <= this.saldo) { this.saldo -= n; return true; } return false; } }

🔓 public

Accesible desde cualquier lugar

🔒 private

Solo accesible dentro de la clase

🔐 protected

Accesible en la clase y sus hijas

🌐 Deber 1: Consumo de una API

Consumo de la API de usuarios — jsonplaceholder.typicode.com

📖¿Qué es una API?

📋 Definición:

Una API (Application Programming Interface) es una interfaz que permite que dos aplicaciones se comuniquen entre sí. Usamos APIs para obtener datos de un servidor externo mediante peticiones HTTP.

🔄

Flujo de consumo de una API

App → Petición HTTP (GET) → Servidor API → Respuesta JSON → App muestra los datos

// Consumo de API con fetch() en JavaScript const url = "https://jsonplaceholder.typicode.com/users"; fetch(url) .then(response => response.json()) .then(data => console.log(data)) .catch(error => console.log("Error:", error));
  • Se usa el método GET para obtener datos
  • La respuesta llega en formato JSON
  • Se maneja con .then() o async/await

🔗API Utilizada

🌐 Endpoint:

https://jsonplaceholder.typicode.com/users

🔐 Deber 2: Autenticación

Email/Password y Google Sign-In con Firebase Authentication — Kotlin (Android)

📖¿Qué es Firebase Authentication?

📋 Definición:

Firebase Authentication es un servicio de Google que permite autenticar usuarios de forma segura usando distintos proveedores: correo/contraseña, Google, Facebook, etc.

🔄

Flujo de Autenticación

Usuario ingresa credenciales → Firebase verifica → Retorna token de sesión → App permite acceso

  • No necesitas manejar contraseñas manualmente
  • Firebase cifra y protege los datos de los usuarios
  • Soporta múltiples proveedores de identidad
  • Provee un objeto FirebaseUser con los datos del usuario activo

⚙️Configuración en build.gradle

// build.gradle (app) implementation("com.google.firebase:firebase-auth-ktx") implementation("com.google.android.gms:play-services-auth:20.7.0")

📧Autenticación con Email/Password

private val auth = FirebaseAuth.getInstance() // REGISTRO fun registrar(email: String, password: String) { auth.createUserWithEmailAndPassword(email, password) .addOnCompleteListener { task -> if (task.isSuccessful) Toast.makeText(this, "Registro exitoso", Toast.LENGTH_SHORT).show() } } // INICIO DE SESIÓN fun iniciarSesion(email: String, password: String) { auth.signInWithEmailAndPassword(email, password) .addOnCompleteListener { task -> if (task.isSuccessful) Toast.makeText(this, "Bienvenido ${auth.currentUser?.email}", Toast.LENGTH_SHORT).show() } } // CERRAR SESIÓN fun cerrarSesion() { auth.signOut() }

🔵Autenticación con Google

val gso = GoogleSignInOptions.Builder(GoogleSignInOptions.DEFAULT_SIGN_IN) .requestIdToken(getString(R.string.default_web_client_id)) .requestEmail().build() googleSignInClient = GoogleSignIn.getClient(this, gso) // Autenticar en Firebase con el token de Google private fun firebaseAuthConGoogle(idToken: String) { val credential = GoogleAuthProvider.getCredential(idToken, null) auth.signInWithCredential(credential) .addOnCompleteListener { task -> if (task.isSuccessful) Toast.makeText(this, "Bienvenido ${auth.currentUser?.displayName}", Toast.LENGTH_SHORT).show() } }

👤Obtener usuario actual

val user = FirebaseAuth.getInstance().currentUser if (user != null) { val nombre = user.displayName val email = user.email val uid = user.uid } else { // No hay sesión → redirigir a Login }

🔥 Deber 3: CRUD con Realtime Database

Crear, Leer, Actualizar y Eliminar datos con Firebase — Kotlin (Android)

📖¿Qué es Firebase Realtime Database?

📋 Definición:

Firebase Realtime Database es una base de datos NoSQL en la nube que sincroniza datos en tiempo real. Los datos se almacenan en formato JSON.

☁️

Sincronización en tiempo real

App escribe dato → Firebase actualiza → Todos los dispositivos reciben el cambio al instante

  • Base de datos NoSQL en la nube
  • Sincronización en tiempo real
  • Funciona en modo offline
  • Datos en árbol JSON

➕CREATE

val ref = FirebaseDatabase.getInstance().getReference("productos") val id = ref.push().key!! ref.child(id).setValue(Producto(nombre, precio, stock)) .addOnSuccessListener { Toast.makeText(this, "Creado ✓", Toast.LENGTH_SHORT).show() }

📋READ

ref.addValueEventListener(object : ValueEventListener { override fun onDataChange(snapshot: DataSnapshot) { val lista = mutableListOf<Producto>() for (item in snapshot.children) { item.getValue(Producto::class.java)?.let { lista.add(it) } } adapter.actualizarLista(lista) } override fun onCancelled(error: DatabaseError) { } })

✏️UPDATE

ref.child(id).updateChildren(mapOf("precio" to nuevoPrecio, "stock" to nuevoStock)) .addOnSuccessListener { Toast.makeText(this, "Actualizado ✓", Toast.LENGTH_SHORT).show() }

🗑️DELETE

ref.child(id).removeValue() .addOnSuccessListener { Toast.makeText(this, "Eliminado ✓", Toast.LENGTH_SHORT).show() }

➕ CREATE

push().key + setValue()

📋 READ

addValueEventListener()

✏️ UPDATE

updateChildren()

🗑️ DELETE

removeValue()

🗄️ Deber 4: CRUD con Room

Persistencia de datos local con Room Database — Kotlin (Android)

📖¿Qué es Room?

📋 Definición:

Room es una biblioteca de Android Jetpack que proporciona una capa de abstracción sobre SQLite. Permite trabajar con bases de datos locales usando anotaciones de Kotlin.

📱

Persistencia local sin internet

Los datos se guardan directamente en el dispositivo. Funciona sin conexión.

  • Abstracción sobre SQLite
  • Usa anotaciones para definir tablas
  • Compatible con LiveData y Flow
  • Verifica SQL en tiempo de compilación

1️⃣@Entity — La tabla

@Entity(tableName = "productos") data class Producto( @PrimaryKey(autoGenerate = true) val id: Int = 0, @ColumnInfo(name = "nombre") val nombre: String, @ColumnInfo(name = "precio") val precio: Double, @ColumnInfo(name = "stock") val stock: Int )

2️⃣@Dao — Las operaciones CRUD

@Dao interface ProductoDao { @Insert(onConflict = OnConflictStrategy.REPLACE) suspend fun insertar(p: Producto) @Query("SELECT * FROM productos ORDER BY nombre ASC") fun obtenerTodos(): Flow<List<Producto>> @Update suspend fun actualizar(p: Producto) @Delete suspend fun eliminar(p: Producto) }

3️⃣@Database — Punto de entrada

@Database(entities = [Producto::class], version = 1, exportSchema = false) abstract class AppDatabase : RoomDatabase() { abstract fun productoDao(): ProductoDao companion object { @Volatile private var INSTANCE: AppDatabase? = null fun getInstance(context: Context) = INSTANCE ?: synchronized(this) { Room.databaseBuilder(context.applicationContext, AppDatabase::class.java, "mi_bd") .build().also { INSTANCE = it } } } }

4️⃣Uso en la Activity

dao = AppDatabase.getInstance(this).productoDao() // Observar en tiempo real lifecycleScope.launch { dao.obtenerTodos().collect { lista -> adapter.actualizarLista(lista) } } // Insertar lifecycleScope.launch { dao.insertar(Producto(nombre = "Laptop", precio = 999.99, stock = 5)) } // Eliminar lifecycleScope.launch { dao.eliminar(producto) }

@Entity

Define la tabla y columnas

@Dao

Define operaciones CRUD

@Database

Punto de entrada, crea la BD

Flow

Actualiza la UI en tiempo real
